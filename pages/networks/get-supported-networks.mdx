# List supported networks

Returns every network Knit supports, the tokens available on each, and whether
collections and payouts are currently enabled for them.

<Endpoint method="GET" path="/api/v1/networks" />

<Meta>
  <Chip label="Auth" value="None — public endpoint" />
</Meta>

<Callout type="warning">
  Availability changes. A chain can be paused for payouts while still accepting
  collections, and individual tokens can be toggled independently of their
  network. Read this endpoint at startup or on a schedule rather than
  hardcoding a list.
</Callout>

## Request

No authentication is required.

```bash filename="cURL"
curl "https://api-prod.useknit.io/api/v1/networks" \
  -H "Accept: application/json"
```

## Fields

<Fields>
  <Field name="identifier" type="string">
    The value to send as `network` in every other request — for example
    `MATIC_MAINNET`. Use this, not `name`.
  </Field>
  <Field name="name" type="string">
    A display label for your UI.
  </Field>
  <Field name="collectionStatus" type="string">
    `ACTIVE` or `INACTIVE`. Whether
    [collections](/collections/create-a-collection) can be created on this
    network.
  </Field>
  <Field name="payoutStatus" type="string">
    `ACTIVE` or `INACTIVE`. Whether
    [payouts](/payouts/create-a-single-payout) can be sent on this network.
  </Field>
  <Field name="tokens" type="object[]">
    The tokens on this network, each with its own `collectionStatus` and
    `payoutStatus`. A token can be inactive on an otherwise active network — so
    check both levels.
  </Field>
  <Field name="tokens[].address" type="string">
    The token's contract address on that chain.
  </Field>
</Fields>

<Callout type="info">
  Use this endpoint to drive the network and token pickers in your product. It
  keeps your UI in step with what the API will actually accept, and avoids
  showing customers an option that will fail at submission.
</Callout>
