# List payouts

Returns the payouts belonging to your business, newest first. The list is
paginated. Pass `merchantReference` to find the payout you created with that
reference.

<Endpoint method="GET" path="/api/v1/payouts" />

<Meta>
  <Scope value="payouts:read" />
  <Chip label="Auth" value="Bearer token" />
</Meta>

<Callout type="warning">
  This endpoint used to return every payout in one response. It now returns
  one page of 15 payouts by default. Read `pagination.lastPage` and fetch each
  page, or set `perPage` up to `100`.
</Callout>

## Query parameters

<Fields>
  <Field name="merchantReference" type="string" required={false}>
    Only the payout you created with this `merchantReference`. The list has one
    item if that payout exists, and is empty if it does not. Maximum 255
    characters. If you send the parameter, it must not be empty.
  </Field>
  <Field name="status" type="string" required={false}>
    Only payouts with this status, for example `FAILED`. See the
    [status lifecycle](/payouts/create-a-single-payout#status-lifecycle).
  </Field>
  <Field name="network" type="string" required={false}>
    Only payouts on this network, for example `TRON_MAINNET`.
  </Field>
  <Field name="token" type="string" required={false}>
    Only payouts of this token, for example `USDT`.
  </Field>
  <Field name="from" type="string" required={false}>
    Only payouts created at or after this time. An ISO 8601 date or date and
    time, for example `2026-11-01T00:00:00Z`. A time without an offset is read
    as UTC.
  </Field>
  <Field name="to" type="string" required={false}>
    Only payouts created before this time. A payout created exactly at `to` is
    not included. Must be later than `from`.
  </Field>
  <Field name="page" type="integer" required={false} defaultValue="1">
    The page to fetch. Minimum `1`, maximum `10000`.
  </Field>
  <Field name="perPage" type="integer" required={false} defaultValue="15">
    Payouts per page. Minimum `1`, maximum `100`.
  </Field>
</Fields>

## Request

```bash filename="cURL"
curl "https://api-prod.useknit.io/api/v1/payouts" \
  -H "Authorization: Bearer $KNIT_ACCESS_TOKEN" \
  -H "Accept: application/json"
```

Find one payout by your reference:

```bash filename="cURL"
curl -G "https://api-prod.useknit.io/api/v1/payouts" \
  -H "Authorization: Bearer $KNIT_ACCESS_TOKEN" \
  -H "Accept: application/json" \
  --data-urlencode "merchantReference=INV-2045"
```

<Callout type="info">
  Reconcile on `merchantReference` — it is the value you control and the one
  that stays stable across your own retries. When you are not sure whether a
  payout request reached us (a timeout, a `5xx`), look it up with
  `?merchantReference=` before you send it again. One item means the payout
  exists. An empty list means it was not created, or the first request is
  still being processed: send it again with the **same** reference, never a new
  one.
</Callout>

<Callout type="warning">
  References are unique across all Knit businesses, not only yours. If a
  create request gets the duplicate `400` but this lookup returns an empty
  list, another business uses that reference. Your payout was not created. Use
  references that only you generate, for example your company name plus an
  invoice ID.
</Callout>

## Errors

| Status | Cause |
| ------ | ----- |
| `400` | A query parameter is not valid, for example an empty `merchantReference`, `perPage` above `100` or `to` before `from`. The body carries an `errors` entry for the parameter |
| `401` | Missing or invalid token, IP not allow-listed, or missing `payouts:read` |
