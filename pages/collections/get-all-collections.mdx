# List collections

Returns your business's collections, newest first.

<Endpoint method="GET" path="/api/v1/collections" />

<Meta>
  <Scope value="collections:read" />
  <Chip label="Auth" value="Bearer token" />
</Meta>

## Query parameters

All filters are optional and combine with AND.

<Fields>
  <Field name="status" type="string" required={false}>
    Exact match on collection status, for example `PENDING` or `SUCCESSFUL`.
  </Field>
  <Field name="network" type="string" required={false}>
    Exact match on network identifier, for example `MATIC_MAINNET`.
  </Field>
  <Field name="token" type="string" required={false}>
    Exact match on token symbol, for example `USDT`.
  </Field>
  <Field name="minAmount" type="number" required={false}>
    Only collections whose `tokenAmount` is greater than or equal to this.
  </Field>
  <Field name="maxAmount" type="number" required={false}>
    Only collections whose `tokenAmount` is less than or equal to this.
  </Field>
  <Field name="startDate" type="date" required={false}>
    Only collections created at or after this date.
  </Field>
  <Field name="endDate" type="date" required={false}>
    Only collections created at or before this date.
  </Field>
</Fields>

<Callout type="info">
  This endpoint returns the full filtered result set — there is no `pagination`
  object in the response. Narrow with `startDate` / `endDate` rather than
  fetching everything on a schedule.
</Callout>

## Request

```bash filename="cURL"
curl -G "https://api-prod.useknit.io/api/v1/collections" \
  -H "Authorization: Bearer $KNIT_ACCESS_TOKEN" \
  -H "Accept: application/json" \
  --data-urlencode "status=SUCCESSFUL" \
  --data-urlencode "token=USDT" \
  --data-urlencode "startDate=2024-08-01"
```

## Errors

| Status | Cause |
| ------ | ----- |
| `401` | Missing or invalid token, IP not allow-listed, or missing `collections:read` |
| `422` | A filter value has the wrong type, for example a non-date `startDate`. Query-parameter failures on this endpoint return the full envelope with `errors` — see [Requests & responses](/conventions#validation-errors) |
