# Create a wallet

Provisions a reusable address you can hand out repeatedly — for a customer
balance, a recurring subscriber, or any long-lived deposit destination. Unlike a
[collection](/collections/create-a-collection), an API wallet does not expire
and accepts any number of deposits.

<Endpoint method="POST" path="/api/v1/wallets" />

<Meta>
  <Scope value="wallets:write" />
  <Chip label="Auth" value="Bearer token" />
</Meta>

## Supported networks

| Network | Identifier | Type |
| ------- | ---------- | ---- |
| Polygon | `MATIC_MAINNET` | EVM |
| Polygon Amoy (testnet) | `MATIC_AMOY` | EVM |
| BNB Smart Chain | `BSC_MAINNET` | EVM |
| Ethereum | `ETHEREUM_MAINNET` | EVM |
| Base | `BASE_MAINNET` | EVM |
| Tron | `TRON_MAINNET` | Tron |

USDT is not available on Base.

## One address on several networks

An EVM wallet can receive deposits on more than one EVM network. List the
networks in `networks` when you create the wallet. Knit gives the wallet one
address, and that address receives deposits on every network in the list.

- **You can add EVM networks later.** Send them in `networks` to
  [Update a wallet](/wallets/update-single-wallet). The address stays the
  same. Knit never removes a network from a wallet.
- **Knit watches only the listed networks.** Tell your customers which
  networks they can use.
- **Tron has its own wallet.** A wallet holds EVM networks or Tron, not both.
  A Tron wallet uses `TRON_MAINNET` only.

<Callout type="warning">
  The address is the same on every EVM network. If a customer sends funds to it
  on a network that is not in `networks`, Knit does not detect the deposit and
  does not credit your API account. Add the network first.
</Callout>

## Body

Provide either `network` or `networks` — not both.

<Fields>
  <Field name="network" type="string" required={false}>
    A single network identifier. Required unless `networks` is supplied.
  </Field>
  <Field name="networks" type="string[]" required={false}>
    One or more network identifiers of the same type. The wallet gets one
    address that receives deposits on all of them. Required unless `network`
    is supplied; must contain at least one entry.
  </Field>
</Fields>

<Callout type="warning">
  Sending `network` and `networks` in the same request is a validation error.
  Pick one form.
</Callout>

## Request

```bash filename="Single network"
curl -X POST "https://api-prod.useknit.io/api/v1/wallets" \
  -H "Authorization: Bearer $KNIT_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "network": "MATIC_MAINNET" }'
```

```bash filename="Multiple networks"
curl -X POST "https://api-prod.useknit.io/api/v1/wallets" \
  -H "Authorization: Bearer $KNIT_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "networks": ["MATIC_MAINNET", "BSC_MAINNET", "BASE_MAINNET"] }'
```

## What happens on a deposit

Deposits into an API wallet are recorded as
[wallet transactions](/wallets/get-single-wallet-transactions) and credited to
your API account, so the funds are immediately available to
[payouts](/payouts/create-a-single-payout). A
`WALLET_FUNDING_SUCCESSFUL` webhook is delivered for each confirmed deposit.

Each deposit records the network it arrived on. For a wallet on several
networks, read `network` on the wallet transaction, or `transaction.network`
in the webhook, to see which one the customer used.

## Errors

| Status | Cause |
| ------ | ----- |
| `401` | Missing or invalid token, IP not allow-listed, or missing `wallets:write` |
| `400` | Neither `network` nor `networks` was supplied, both were supplied, a network identifier is not supported, or `networks` mixes EVM and Tron networks |
