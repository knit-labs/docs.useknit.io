# List wallets

Returns the API wallets your business has created, across every network,
newest first. The list is paginated.

<Endpoint method="GET" path="/api/v1/wallets" />

<Meta>
  <Scope value="wallets:read" />
  <Chip label="Auth" value="Bearer token" />
</Meta>

<Callout type="warning">
  This endpoint used to return every wallet in one response. It now returns
  one page of 15 wallets by default. Read `pagination.lastPage` and fetch each
  page, or set `perPage` up to `100`.
</Callout>

## Query parameters

<Fields>
  <Field name="page" type="integer" required={false} defaultValue="1">
    The page to fetch. Minimum `1`, maximum `10000`.
  </Field>
  <Field name="perPage" type="integer" required={false} defaultValue="15">
    Wallets per page. Minimum `1`, maximum `100`.
  </Field>
  <Field name="from" type="string" required={false}>
    Only wallets created at or after this time. An ISO 8601 date or date and
    time, for example `2026-11-01T00:00:00Z`. A time without an offset is read
    as UTC.
  </Field>
  <Field name="to" type="string" required={false}>
    Only wallets created before this time. The wallet created exactly at `to`
    is not included. Must be later than `from`.
  </Field>
</Fields>

## Request

```bash filename="cURL"
curl -G "https://api-prod.useknit.io/api/v1/wallets" \
  -H "Authorization: Bearer $KNIT_ACCESS_TOKEN" \
  -H "Accept: application/json" \
  --data-urlencode "perPage=100" \
  --data-urlencode "page=1"
```

<Callout type="info">
  Keep the mapping between your customers and wallet IDs on your side. Use this
  list to load that mapping once, not on each request. To see what your
  wallets received, use [List deposits](/wallets/list-deposits).
</Callout>

## Errors

| Status | Cause |
| ------ | ----- |
| `400` | A query parameter is not valid, for example `perPage` above `100` or `to` before `from`. The body carries an `errors` entry for the parameter |
| `401` | Missing or invalid token, IP not allow-listed, or missing `wallets:read` |
