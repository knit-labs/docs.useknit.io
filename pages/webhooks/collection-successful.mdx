# `COLLECTION_SUCCESSFUL`

Delivered when a collection's funds have been credited to your API account.
This is the event to act on: the money is yours and available to
[pay out](/payouts/create-a-single-payout).

<Meta>
  <Chip label="Envelope" value="body wrapper" />
  <Chip label="Keys" value="snake_case" />
</Meta>

Delivered to the collection's `merchantCallbackUrl`, falling back to your
business webhook URL.

## Partial payments

`status` is `SUCCESSFUL_PARTIAL` when less than the requested amount arrived.
The received amount is still credited, so treat this event as money-in — but
reconcile the shortfall.

```js filename="Distinguishing full from partial"
const c = payload.collection;
const paidInFull = c.status === "SUCCESSFUL";
const shortfall =
  Number(c.token_amount_requested) - Number(c.token_amount_received ?? 0);
```

<Callout type="warning">
  Always credit your customer against `token_amount_received`, never against
  `token_amount_requested`. Amounts are decimal strings — parse them with a
  decimal library rather than a float.
</Callout>

## Handling

1. Verify the signature and return `2xx` promptly.
2. Look the collection up by `id` on your side and check you have not already
   processed it — this event can arrive more than once.
3. Credit against `token_amount_received`.
4. Fulfil the order.
